## 1. 工具复用：真正的堵点在哪（recon-tools-and-approval.md + design-v1.2.0.md §1）

**结论：`toolFilter` 不是 BYK 的问题所在——BYK 从未设置它，子智能体本来就继承父会话的全部工具。**

| 事实 | 位置 | 原文 |
|---|---|---|
| 子会话组装函数（唯一裁剪点所在） | `C:\coding\DSH\resources\app.asar\dsh\node_modules\@deepseek-ai\dsh-subagent\lib\index.js:510` | `function applyChildComposition(childCtx, parent, composition) {` |
| 继承父 preset 链（=继承父工具注册表） | 同上 :511 | `childCtx.get("agentPresets")?.composeFrom(childCtx, parent.ctx);` |
| **唯一裁剪点** | 同上 :522 | `if (composition.toolFilter !== void 0) childCtx.tools.restrict(composition.toolFilter);` |
| 不 join preset 就什么都看不到（反证） | 同上 :502-504 | `a child that joins no preset sees an empty tool registry and none of its parent's prompt sections` |

BYK 侧全目录 grep `toolFilter|composeFrom|restrict\(|subagents\.start` → **仅 2 处命中，均非 toolFilter**：

```
C:\Projects\byk\dsh-plugin\lib\index.js:18:  * 为什么用子智能体接口而不是自己起进程：`ctx.subagents.start` 支持
C:\Projects\byk\dsh-plugin\lib\index.js:394:     run = await ctx.subagents.start(providerName, {
```

即 `composition.toolFilter === void 0`，:522 整行不执行。

**容量边界**：一个会话可见的工具 = 全局注册项 + 各作用域层叠加 − 该 agent 的 `restrict()` 掩码
（`dsh-tools\lib\index.js:2690` 层链容器、:2707 `ctx.systemPrompt.tools(...)` 注册即可见）；`restrict()` 是**交集**语义
（`dsh-tools\README.md`「Restrict tools per agent」：`masks intersect, scoped registrations stay visible`）。
因此 **子会话工具集 ⊆ 父会话工具集**——放开 ≠ 子智能体能碰父会话碰不到的东西。

真正的三条堵点全在 BYK 自己身上：① 人格把助手塑造成「读 TASK.md、写 RESULT.md」的孤立角色；
② 没有配置项把「继承宿主工具」写成契约；③ 收窄能力默认关闭。

## 3. 客户端模块 `lib\client.js`（impl-notes.md s5b 节）

照抄 `C:\coding\DSH Home\profiles\desktop\node_modules\dsh-approval-gate\client.js`（:14-19 模块包装、
:177-186 当前会话 id、:188-196 事件接口、:204/:222-232/:260-305 字段与去重），**不自创**。

- 导出：`exports.default / exports.apply / exports.inject = ['timer']`；`ctx.get('slots')` 取不到即 `return`。
- 挂两个 slot：`conversation.input.dock`（id `byk-agents.approval-mirror`，**order 31**，原生条 :948 是 30）→ 跨会话提示条；
  `conversation.view`（id `byk-agents.approval-history`，**order 21**，label `跨会话审批`，原生「审批」:959 是 20）。
- 数据源：轮询 `GET /api/auto-approve/events`（**不带 `sessionId`**，可选 `since`），**5 秒**一次；
  每次取 `since = max(0, cursorId - 50)` 回扫 50 条——因为 id 是跨会话共享的全局递增游标，
  多会话并发时单游标可能跳过另一会话较早写入的事件；再用自身 seen Set（>500 条按 cursor-500 裁剪）兜底。
- **硬规则（与原生条零重复）**：`ev.sessionId !== 当前会话 id` 才渲染；当前会话事件直接 `continue`；
  **当前会话 id 解析不出来时本模块什么都不渲染**（宁可空着，也不冒双条风险）。
- 首轮静默基线：开轮询前先 `since=0` 拉一次全量，只推进游标 + 灌去重表，**不为历史事件弹提示**。
  pending（等待人工审批）不自动收起，其余 6 秒收起。
- 降级：`fetch` 失败 / 非 2xx / CORS 失败 → `console.warn` **只打一次**（模块级 `degraded` 标志），之后静默继续轮询；
  事件缺 `id` 或缺 `sessionId` → `continue` 跳过，不崩。
- 来源标注：只有客户端确实给出 `parentSession`/`parentSessionId`/`origin==='subagent'`/`delegationDepth>0`
  时才标「子会话 · <短 id>」，否则一律「其它会话」——**按设计的降级口径，不谎称子会话**（`lib\client.js:106-110,152-169`）。

## 4. 客户端模块为什么一开始没被送到浏览器（client-loading-fix.md）

**结论**：package.json 的客户端声明本身与对照组一致，问题在**运行中的 DSH 进程的客户端模块表里根本没有
`dsh-plugin-byk-agents` 这一项**；另有一处**真实缺陷**：`lib\client.js` 的注册 id 写成了 entry 名 `byk-agents`，
而运行时用的是**包名** `dsh-plugin-byk-agents`。两处已修（`lib\client.js:22` 的 `id:` 改为包名；
`package.json` `exports` 补 `"./package.json"`）。

决定性证据（实测 HTTP，自算 rev）：

| 请求 URL | 状态码 | 响应 |
|---|---|---|
| `/plugins/??dsh-approval-gate/client.js&rev=75ccecf43b33` | **200** | 59033 字节 |
| `/plugins/??dsh-plugin-byk-agents/client.js&rev=...`（修复前后各一次） | **404** | 空 |
| `/api/auto-approve/events` | **200** | `{"events":[]}` |
| `/` | 401 | `dsh web authentication required…` |

同一个 URL 形状、同样自算的 rev，对照组建 200、我们 404 ⇒ 我们的包不在运行时那张表里（`index.js:883-890`），
所以 `compose()` 的清单里就没有它，`__DSH_BOOT__` 自然零命中。
**推断（标注为推断）**：构造时的扫描（`:534-540`）发生在**进程启动那一刻**并缓存 package.json 结果（`:701-704`），
而 `dsh.client`/`exports["./client"]`/`lib\client.js` 都是启动之后才加的，package.json 变更**不触发** entry 变更事件。

对照组的客户端声明原文与产物事实（`dsh-approval-gate 0.5.0`）：`exports` 里 `"./client": "./client.js"`、
`dsh.client = {"platform":"web","inject":[]}`、产物在**包根目录**且**不是打包产物**（文件开头就是手写的
`window.__ModuleLoader__.load({ id: 'dsh-approval-gate', factory: (require) => { ... } })`）。
位置由 `exports["./client"]` 决定，不是约定；字符串形式与带 types 的条件对象都被接受。
URL 规则：`/plugins/??<包名>/client.js&rev=<rev>`。

## 5. 审批可见性：能力的真实边界（recon-tools-and-approval.md (c) + recon-approval-gate.md + design §2）

分三层看，「子会话审批能否被主对话看到」结论逐层不同：

| 层 | 结论 | 判定 |
|---|---|---|
| Host 事件转发层 | `approval/request` 在 `API_REMOTE_FORWARDED_EVENTS` 白名单里、`mode:"waterfall"`、**无会话过滤**（`dsh-api-remotes\lib\index.js:22-25`） | **原生支持** |
| 客户端 pending 注册层 | pending 按 **sessionId 全局登记**，子会话的 pending 会以自己 id 出现在状态表（`dsh-client-ui-session\lib\client.js:342-357` `publishStatus()`；:242-259 `registerPendingInteraction` 是**全局按会话发布**、按 precedence 竞争） | **原生支持** |
| 主对话呈现层 | **不能**。审批卡片挂 `conversation.composer` 槽，渲染的是**当前正在查看的会话**（`dsh-client-ui-approval\lib\client.js:284-310` `answerApproval` → `const sessionId = ctx.sessions.scopeOf(owner)`），子会话的 pending 只有切过去才看得到 | **需要改造（在 DSH 侧）** |

发起/决策链原文：`dsh-user-approval\lib\index.js:128-144` `async request(req)` →
`session.append("approval/asked", { id, toolName, callId?, reason? })`（:132-137，审计写在**请求方自己的会话**）；
`:172-189` `async decide(req, session)` → `if (this.effectivePolicy(session) === "never") return "rejected";`（:175），
后面 `ctx.waterfall(scopeTarget(...), "approval/request", req, () => Promise.resolve("unavailable"))`（:176，默认兜底 fail closed）。
全库只有 3 处监听 `approval/request`：`dsh-acp\lib\index.js:1116`、`dsh-client-ui-approval\lib\client.js:355`、转发白名单。

**为什么子智能体的审批根本看不到（本轮最大的能力缺口）**：
子会话审批策略被 delegation 钉子为 `never`（`subagent-in-process-driver\tests\inheritance.spec.ts:98 / :160`），
语义常量 `user-approval\src\index.ts:73`：`'Approval prompts are disabled in this session: actions that require approval are rejected automatically ...'`；
`:175` 直接 `return "rejected"`。**该动作在子会话里被自动拒绝、根本不产生 approval-gate 事件，镜像条无从显示。**
approval-gate 本身**不读 approval/policy**，只校验 permission preset（`src\index.mjs:1213 / :1218`），
且全文 grep `subagent|child|parent|sub-session` = **0 命中**——它没有父子会话概念。

**要做「子智能体审批弹给人」必须改 DSH 上游**：`packages/subagent/subagent-in-process-driver` 的 delegation 策略继承，
或 `packages/interaction/user-approval` 的 policy 短路分支。**超出 BYK 插件职责范围。**

## 7. 已知边界与未解项（**移交用户 / DSH 上游**）

1. **子智能体的审批看不到。** policy=never 由 DSH 侧钉死，动作在子会话里**自动拒绝**、不产生 gate 事件。
   `lib\client.js` 只能镜像「其它会话」的 gate 事件。要改需 DSH 上游（见 §5）。**这是本轮最大的能力缺口。**
2. **客户端模块必须完整重启 DSH 才会被加载，插件热重载不够。** 清单在进程启动时快照，package.json 变更不触发重算。
   重启后仍 404 = 还有第二处静态阻塞，需要 DSH 启动日志里 `client-modules:` 开头的报错才能继续定位。
3. **RPC 鉴权：secret 必须先 base64url 解码成 32 字节再作 HMAC key。** `.credentials.yaml` 里
   `client-connection/browser-session` 那串 43 字符 base64url 是**编码后的 32 字节密钥**
   （实测 `secretBytes=32`）；直接拿字符串当 HMAC-SHA256 的 key → **401**，body 恰好是 12 字节非 JSON 的 `unauthorized`；
   解码后同一请求 → **200**。
4. **`caps.toolFilter` 真值未核实**：caseB/caseC 里的 caps 是**桩给的**；真实 provider（spawn/fork）capabilities 有没有
   `toolFilter` 字段、`dsh-subagent` 拿到 toolFilter 后是接受还是忽略，均未核实。`inherit-all` 默认路径不受影响。
5. **「其它会话的审批能在主对话看到」未做端到端**：本次实测 `/api/auto-approve/events` 返回 `{"events":[]}`，
   当前就是空的；需要真的制造一次跨会话审批事件才能验收。
6. **`parentSession` 客户端可读性未解**（无浏览器），代码已降级为拿不到就标「其它会话」。
7. **插件注入的子智能体提示词是 BYK 注入部分**（`SUBAGENT_TOOL_REUSE`，`lib\index.js:108-116 / :460`）；
   角色人格的真正来源是 `C:\Projects\byk\byk\roles.py`（python 侧），**本轮未动**。
8. **`test\smoke.test.js` 未补四条 subagentTools 断言**（该文件不在当时的写入范围）；
   四条判定已由独立探针等价覆盖，但**探针断言尚未并回 `test/smoke.test.js`**。
9. **`package.json` `files` 里 `README.md` 与实际文件名 `readme.md` 大小写不一致**（Windows 无影响，
   大小写敏感文件系统上该条目不匹配任何文件；npm 自动包含 README，实际不影响发布）。
   **本轮未改**——属历史遗留，需用户定夺。
10. **设计文档 §7-5**：`approval.request()` 在 `policy === "never"` 时是否**仍然派发** `approval/request` 瀑布事件未读 dispatch 分支；
    不改变「子智能体审批不弹给人」的结论（`:175` 直接 rejected）。
